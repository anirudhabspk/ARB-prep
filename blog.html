AutoResearchBench

Measuring agents' ability to improve and generalize on open ended ML research tasks.

Progress toward Recursive Self Improvement depends on agents that can solve hard, open ended ML research problems quickly while producing solutions that generalize beyond the experiments they can see.

Open-ended research rewards persistent and compounding effort. The predominant paradigm of open-ended task evaluation in ML focuses on attempting these problems in a 1-shot to few-shot setting [1], but these are long-horizon problems, and evals should focus on treating them as such. PostTrainBench studies long horizon agents, but only for LLM post training [2]. A model that is able to compound its efforts more efficiently, and do so for longer, can significantly outperform one that initially appears stronger. This is often experienced in the real-world in ways that are not captured by benchmarks.

Vanilla auto-research evals [3] and other long-horizon benchmarks [4] do not fully capture this either. They reward improvements on feedback available during the run, without separately measuring whether those improvements generalize to held-out data. Long runs can therefore reward solutions that overfit the feedback.

To address these gaps, we introduce AutoResearchBench, a benchmark of open ended ML research tasks designed to measure how quickly agents improve over 24-hour long AutoResearch runs while still generalizing to hidden test data.

Main results

Twenty-one completed reruns are included. Sixteen reruns are still running, so their prior published results remain in the calculations. Two invalid replacements also retain their prior results.

AUARC is the normalized Area under the Auto Research Curve. We compute it as the time-average of the best reward reached during the run. Models score higher when they find better solutions earlier. For hidden test AUARC, we use the hidden test reward of the checkpoint selected by validation at each iteration. The 21 completed replacement runs use their observed 23 hour research window for AUARC. Their plots hold the final score flat through hour 24.

Task relative Elo compares models using hidden test AUARC within each task. We combine these task level comparisons into one rating and set the middle model to 1000. Lines show 95% bootstrap intervals from repeatedly sampling the task set.

      Experimental setup

      We run AutoResearch with Terminus 2 in a 24 hour benchmark window. The 21 completed September 8 replacement runs used 23 hours for research and reserved 1 hour for infrastructure. We extend their final observed score through hour 24 for the plots, but compute AUARC over the 23 hour research window. These extended runs let us measure whether models sustain progress and whether repeated optimization of validation scores leads to overfitting, with gains that fail to generalize to hidden test data.

      Each task uses the Harbor format, with separate work and verifier containers. At the start of each iteration, the model receives the current workspace and the validation scores from earlier iterations. The model has up to 32,000 output tokens per turn. The model then submits one version for validation scoring, and its workspace carries into the next iteration. The model never sees hidden test scores.

      To guard against reward hacking, our adversarial quality control and reward hacking agent inspects task environments and completed model rollouts. We have already used this agent to find issues in several widely used benchmarks and are working with the community to address them (blog coming soon). Models also have no internet access.

      Harnesses can significantly affect performance. We compare all models using the same Terminus 2 harness to isolate model performance and evaluate them fairly. We also run experiments with Claude Code and Codex to investigate behavioral differences in the harness comparison.

      All models used the maximum effort available at the time: max for Claude Fable 5.1, Claude Opus 5, GPT-5.6 Sol, Kimi K3, and GPT-6 Astra; xhigh for Qwen3.8 Max, Muse Spark 1.3, and Grok 4.6; high for Gemini 3.8 Flash.

      Progress over time.

      During the run, the agent optimizes the validation score it can see. We report the Area under the Auto Research Curve (AUARC) to measure how much it improves and how early those improvements arrive.

      2

      Hidden test generalization.

      At each iteration, validation alone selects the checkpoint whose hidden test score enters the curve. We use hidden test AUARC to compare models within each task, then combine those comparisons into a task relative Elo. We also report final hidden test performance so major breakthroughs that happen late remain visible.

      We score each task from 0 to 1. We compare the agent's improvement over a simple baseline with a strong reference result, where available. Validation and hidden-test results first recover the raw task metric, then use the same mapping based on the final hidden-test panel's anchors. This keeps their rewards and the reported generalization gap on one common scale.

      For metrics with a perfect score, we reward proportional reductions in the remaining error. Improving accuracy from 90% to 95% removes half the remaining error.

      Reward formula

      For metrics with a perfect score and a reference result, let d be the distance from perfect performance.

      u=max(0,log(dbaseline/dagent)log(dbaseline/dreference)) Reward=c+(1−c)u1+u

      Here, c is the baseline reward, either 0 or 0.1. This formula applies at or above the baseline. Perfect performance earns 1; results below the baseline earn at most c.

      For tasks without a fixed limit, we compare the amount of improvement over the baseline with the reference improvement. When no reference exists, u counts halvings of the remaining gap. We then use the same reward formula.

        Comparing harnesses

        We compared Codex and Claude Code with Terminus 2 on five tasks, using the same models over 12 hours.

        Average rewards differ across harnesses, but the aggregate hidden test ranking stays the same. Codex and Claude Code submit more than Terminus 2. Codex’s lower test AUARC is driven by Shortest CI, where validation improvements stopped transferring to the hidden test earlier than with Terminus 2.

        These results support our choice to use Terminus 2 for all models. It provides a consistent setup and preserves the aggregate model ranking seen with native harnesses in this comparison.
