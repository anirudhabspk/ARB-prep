Progress toward Recursive Self Improvement depends on agents that can solve hard, open ended ML research problems quickly while producing solutions that generalize beyond the experiments they can see.

Open-ended research rewards persistent and compounding effort. The predominant paradigm of open-ended task evaluation in ML focuses on attempting these problems in a 1-shot to few-shot setting [1], but these are long-horizon problems, and evals should focus on treating them as such. PostTrainBench studies long horizon agents, but only for LLM post training [2]. A model that is able to compound its efforts more efficiently, and do so for longer, can significantly outperform one that initially appears stronger. This is often experienced in the real-world in ways that are not captured by benchmarks.

Vanilla auto-research evals [3] and other long-horizon benchmarks [4] do not fully capture this either. They reward improvements on feedback available during the run, without separately measuring whether those improvements generalize to held-out data. Long runs can therefore reward solutions that overfit the feedback.

To address these gaps, we introduce AutoResearchBench, a benchmark of open ended ML research tasks designed to measure how quickly agents improve over 24-hour long AutoResearch runs while still generalizing to hidden test data.

Measuring both requires separating the feedback the agent can see from the hidden performance used to rank it. We therefore evaluate each run along two axes:

1

Progress over time.

During the run, the agent optimizes the validation score it can see. We report the Area under the Auto Research Curve (AUARC) to measure how much it improves and how early those improvements arrive.

2

Hidden test generalization.

At each iteration, validation alone selects the checkpoint whose hidden test score enters the curve. We use hidden test AUARC to compare models within each task, then combine those comparisons into a task relative Elo. We also report final hidden test performance so major breakthroughs that happen late remain visible.

Experimental setup

We run AutoResearch with Terminus 2 on each task for 24 hours of total wall-clock time. These extended runs let us measure whether models sustain progress and whether repeated optimization of validation scores leads to overfitting, with gains that fail to generalize to hidden test data.

Each task uses the Harbor format, with separate work and verifier containers. At the start of each iteration, the model receives the current workspace and the validation scores from earlier iterations. The model has up to 32,000 output tokens per turn. The model then submits one version for validation scoring, and its workspace carries into the next iteration. The model never sees hidden test scores.

To guard against reward hacking, our adversarial quality control and reward hacking agent inspects task environments and completed model rollouts. We have already used this agent to find issues in several widely used benchmarks and are working with the community to address them (blog coming soon). Models also have no internet access.

Harnesses can significantly affect performance. We compare all models using the same Terminus 2 harness to isolate model performance and evaluate them fairly. We also run experiments with Claude Code and Codex to investigate behavioral differences in the Harness ablations section.

All models used the maximum effort available at the time: max for Claude Fable 5.1, Claude Opus 5, GPT-5.6 Sol, Kimi K3, and GPT-6 Astra; xhigh for Qwen3.8 Max, Muse Spark 1.3, and Grok 4.6; high for Gemini 3.8 Flash.

Results

AUARC is the normalized Area under the Auto Research Curve. We compute it by averaging the best score reached at each of the 15 iterations. Models score higher when they find better solutions earlier. For hidden test AUARC, we use the hidden test score of the checkpoint selected by validation at each iteration.

      Harness ablations

      We compared Codex and Claude Code with Terminus 2 on five tasks, using the same models and comparing the first 12 hours.

      Average scores differ across harnesses, but the aggregate hidden test ranking stays the same. Both Codex and Claude Code submit more than Terminus 2 in these runs. Codex has a larger drop from validation to hidden test scores, mostly due to one task. Claude Code has no average drop. These results do not establish that extra submissions cause overfitting.

      These results support our choice to use Terminus 2 for all models. It provides a consistent setup and preserves the aggregate model ranking seen with native harnesses in this comparison.
